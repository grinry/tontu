# Mobile working instructions

Read the repository's [AGENTS.md](../../AGENTS.md) and [coding rules](../../docs/coding-rules.md), then [mobile docs](./docs/README.md). Prioritize mobile performance and platform compatibility.

- Features live in `src/domains/<domain>/`. No cross-domain imports. Reused code lives in `src/shared/`; App.tsx and future navigation compose domain public entry points.
- Backend requests and feature state belong to their owning domain. Only public configuration belongs on mobile; never import backend source, database clients, or provider credentials.
- Use Biome for lint/format and strict TypeScript. Keep mobile structure/infrastructure/coding docs current with changes.

## Expo version and dependencies

Expo APIs change by SDK. Read the installed `expo` major in package.json, consult `https://docs.expo.dev/versions/v<major>.0.0/`, and use `https://docs.expo.dev/llms.txt` for guides before changing Expo, EAS, or React Native APIs.

Use `pnpm exec expo install <package>` for SDK-compatible packages after obtaining any required production-dependency approval. Preserve exact versions and the root pnpm lockfile. Diagnose compatibility with `pnpm exec expo install --check` and Expo Doctor when relevant.

## Navigation and native builds

The starter currently has one health screen and no router. When navigation is needed, use Expo Router after dependency approval; route files belong in `src/app/`, while feature implementations stay in domains. Do not add a navigation system before it is needed.

Native ios/android directories are generated by Expo Continuous Native Generation. Do not create or edit them by hand; use app.json and configuration plugins. Expo Go only includes its bundled native modules; custom native dependencies need a development build.

For mobile changes, run `pnpm --filter @tontu/mobile typecheck` and `build`, plus root `pnpm check`. Signed/EAS builds require the Expo project and credentials described in [infrastructure](./docs/infrastructure.md).
