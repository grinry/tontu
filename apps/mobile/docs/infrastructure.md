# Mobile infrastructure and builds

## Toolchain and commands

The app uses Expo SDK 57, React Native, strict TypeScript, and repository Biome configuration. Use Node 24.19.0 and pnpm 10.32.1. Check matching Expo SDK docs before changing framework/native APIs and use `pnpm exec expo install` for SDK-compatible dependencies after any required approval.

| Command from repository root | Behavior |
| --- | --- |
| `pnpm dev:mobile` | Start Expo |
| `pnpm --filter @tontu/mobile ios` / `android` | Start Expo for the simulator/emulator |
| `pnpm --filter @tontu/mobile typecheck` | Type-check mobile code |
| `pnpm --filter @tontu/mobile build` | Export Android/iOS Hermes bundles to dist/ |
| `pnpm --filter @tontu/mobile build:ios` | Local native Release build; needs Xcode |
| `pnpm --filter @tontu/mobile build:android` | Local native release build; needs Android SDK |
| `pnpm --filter @tontu/mobile exec expo install --check` | Validate Expo dependency compatibility |

Bundle export is not a signed store binary. Native ios/android directories are generated by Expo Continuous Native Generation and are ignored by Git; configure native behavior through app.json/config plugins. Do not edit generated native files by hand.

## Backend connectivity and public configuration

EXPO_PUBLIC_API_URL overrides the backend base URL. Without it, iOS uses `http://localhost:4111` and the Android emulator uses `http://10.0.2.2:4111`. On a physical phone use the development computer's LAN address. Do not copy the example's localhost value unchanged for Android/physical-device testing.

The health feature calls `GET /v1/health`, validates its response, and displays connection/database status. It does not depend on Mastra being enabled. Configuration is public and embedded in Expo bundles; never put credentials/secrets in EXPO_PUBLIC variables. Turbo hashes EXPO_PUBLIC_API_URL for bundle builds.

## Native/cloud builds

app.json currently uses `com.grinry.tontu` for iOS/Android bundle identifiers. Confirm identifiers before registering the app. eas.json has preview/internal-distribution and production profiles, but no Expo/EAS project or signing credentials have been linked.

For cloud builds, link the project to an Expo account and configure credentials, then run EAS CLI from the mobile app directory. Add a development-build profile when custom native modules or that workflow is needed. Expo Go includes only its bundled modules.

Signed native builds and store submission are separate from the local JavaScript bundle checks. Keep this document current with identifiers, dependencies, API URLs, native configuration, profiles, and signing/deployment choices.
